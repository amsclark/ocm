Case management for legal aid.

OCM tracks intakes, cases, clients and contacts, calendars and deadlines, time entries, documents, and the reporting a legal aid program needs for its funders, including LSC case service reporting. It runs in a web browser.

Run it in two commands Read the docs 
git clone https://github.com/amsclark/ocm.git
cd ocm
cp .env.example .env   # then set DB_PASSWORD
docker compose up -d

Needs Docker with the Compose plugin. Nothing else.

Try it

The first start builds the image, loads the schema, and prints the generated admin password when it finishes.

1. Watch the first start

docker compose logs -f app

2. Log in

Open http://127.0.0.1:8080/cms/ and sign in with the admin password from the log.

3. Check it worked

tests/smoke.sh

That should end with 261 passed, 0 failed.

Before you put real client data in it, read Installation with Docker: configuration, backups, and upgrades.

What it does

The day-to-day work of a legal aid program, in one place.

Intake

Start an intake, run financial and citizenship eligibility, check for conflicts and duplicates, then review and assign it.

Cases and contacts

Clients, adverse parties, and contacts on every case, with merging of duplicates and peer case transfer.

Calendar and deadlines

Shared calendars, ticklers, and iCal feeds so staff see what is due.

Time and documents

Timeslips on every case. Uploaded documents are indexed for search, PDFs and WordPerfect included.

Document assembly

Form letters and generated documents from case data, with template tags you configure.

Reporting

Built-in reports plus MegaReport for ad hoc queries, and the case service reporting LSC grantees need.

Sign-in security

Multi-factor authentication, single sign-on, breached password checks, forced password change, and re-authentication for sensitive actions.

Menus and customization

Editable menus, custom fields, and HTML fields, so the system fits your program rather than the reverse.

Requirements

For running it directly rather than in a container.

ComponentVersion
PHP8.0 – 8.3, with mysqli, mbstring and zip
MariaDB10.6 or newer, or MySQL 8.0
Apache2.4, with mod_rewrite and mod_headers

Three optional tools

Each one enables a single feature. Leave one out and that feature fails quietly: the upload still succeeds, but document search will not find its contents.

  • pdftotext (poppler-utils) indexes the text of uploaded PDFs
  • htmldoc renders reports to PDF
  • strings (binutils) indexes WordPerfect documents

httpd-config/ocm.conf is a ready-made Apache configuration. Use it. Among other things it makes cms-custom unreachable over HTTP, and that directory holds your database password.

Security

Read SECURITY.md before running this anywhere that holds real client data. It sets out what is supported, what is in scope, and how to report a vulnerability privately.

Put TLS in front of it

Nothing in this repository terminates HTTPS. The in-application setting named "Allow Only Secure (HTTPS) Logins" sends a redirect and does no more than that. The web server is what enforces HTTPS.

Report vulnerabilities privately

For anything that looks like a vulnerability, do not open an issue. Follow the process in SECURITY.md.

What this repository is

OCM is a fork of Pika CMS, which Aaron Worley released under the GPL. This repository holds the 2019 feature set, and it stays there on purpose.

Development since then has continued in a private fork, which is where new features go. What comes back here is security work and bug fixes, backported from that fork. So this repository gets more secure and more correct over time without growing new features, which keeps it a stable base for anyone running it or building on it.

Commercial hosting and support are available from Case Management Corporation, the maintainer of this repository.

Contributing

Bug reports and pull requests are welcome on GitHub. Two things will get a pull request merged faster:

  • tests/smoke.sh passes
  • php -l is clean on every file you touched

CI checks both, on PHP 8.2.

Please do not send new features. They will not be merged here. A feature idea is still worth an issue; it may land in the private fork and reach you that way if you are a hosting customer.
